# 智慧树 (zhihuishu.com) 支持路线图

> **状态：✅ M0–M2 完成（2026-09-12）—— M3 视频 / M4 答题待启动。** 本文是执行蓝图：方法论已定（双轨调研，不重复造轮子），候选参考已列出初始线索（时效性均未验证），调研问题与产出物已定义。

## 1. 目标

在现有超星自动化能力之上，为智慧树（知到）提供同级别支持：

- 账号登录态管理与多账号并发（复用现有账号体系思路）；
- 课程 / 章节扫描与学习进度读取；
- 视频类章节自动完成（含倍速 / 静音 / 防暂停策略）；
- 弹题、章节测验与作业的自动作答（接入现有 AI 答题路由：豆包 / DeepSeek）。

## 2. 非目标（当前阶段）

- 不承诺与超星功能 100% 对齐：以智慧树实际课程形态为准，逐项评估；
- 不做付费内容代购、批量注册等账号层面的越界操作；
- 在 M0 调研完成前，不写任何实现代码；
- 不复制无许可证或许可证不明项目的代码（见 §3 调研纪律）。

## 3. 调研方法论：双轨并行，不重复造轮子

**总纲**：智慧树自动化已有大量现成实现，先穷尽式扫描消化它们的思路，再用我们自己的工具链实地验证现状。两条轨道的产出在 M0 末合流成一份调研报告（`docs/reports/analysis/ZHIHUISHU_ANALYSIS_*.md`）。

### Track A —— 现有实现扫描（四大来源）

| 来源 | 检索方式 | 关注点 |
| --- | --- | --- |
| GitHub | 搜 `zhihuishu` / `知到` / `zhihuishu-auto` 等，按 star 与最近提交排序 | Python/Node 项目架构、接口逆向成果、维护活跃度 |
| Greasy Fork | [zhihuishu.com 站点合集](https://greasyfork.org/zh-CN/scripts/by-site/zhihuishu.com) | DOM 选择器、播放器控制、弹题处理、安装量（≈实测有效性代理指标） |
| Userscript.Zone | 搜 `zhihuishu` | 补充 GreasyFork 之外的脚本生态 |
| OpenUserJS | 搜 `zhihuishu` | 同上，覆盖面较窄但可能有遗珠 |

产出物：**参考矩阵**——每个项目记录：技术路线（浏览器 / 油猴 / 接口直连）、覆盖能力（视频 / 弹题 / 作业 / 考试）、最后更新时间、许可证、可借鉴点、已失效部分。

**调研纪律**：参考逻辑 ≠ 复制代码。许可证不明或无许可证的项目只提炼思路，不搬代码；脚本本体放 `references/`（git 忽略，沿用超星参考脚本模式）；有许可证且兼容 MIT 的（如 [Zhihuishu-Automatic-Answering](https://github.com/Looong01/Zhihuishu-Automatic-Answering)，MIT）可在 PR 中注明来源后按许可证引用。

### Track B —— 实地勘察（DOM / 布局 / 导航）

用现有 `playwright-cli` 工具链（`-s=zhihuishu-chrome` 持久会话）对以下对象做快照与结构笔记：

1. **登录流**：账号密码页 / 短信验证码 / 扫码入口，登录态 Cookie 生命周期；
2. **课程页布局**：章节目录树 DOM、进度标记、章节类型图标（视频 / 图文 / 测验）；
3. **导航流转**：学习页 URL 模式、章节间跳转方式（SPA 路由还是页面跳转）；
4. **播放器**：video 元素结构、倍速 / 静音 / 画质控件的选择器、进度心跳上报时机；
5. **答题层**：弹题容器、章节测验表单、作业页的题型结构（对照超星 solvers 的题型抽象）。

产出物：DOM 选择器清单 + 页面流转图（放本目录或 `docs/design/`）。

**为什么 Track B 不可省**：第三方脚本的选择器随平台改版批量失效是常态（GreasyFork 评论区即失效证据库）；Track A 的思路必须经 Track B 在当前版本页面上重新验证后才能进设计。

## 6. 与现有架构的衔接（设想，待 M0 结论修正）

- 平台抽象：按 [docs/standards/directory.md](../standards/directory.md) §3 的目标布局，将通用编排 / AI 路由 / 内存治理抽为 `core/`，超星实现迁入 `platforms/chaoxing/`，智慧树新增 `platforms/zhihuishu/`。抽取边界以 Q1–Q8 的结论为准。
- 若 Q8 选浏览器路线：智慧树模块复用现有 browser engine（会话 / 快照 / 点击原语）与 RAM 治理，主要新增选择器层与题型适配层。
- 前端：复用现有任务 / 泳道 / 工单 UI，平台差异通过课程数据模型上的 `platform` 字段表达，不新增平台专属视图。
- 凭据：沿用 `data/passwords/` 目录，按 Q7 结论决定文件组织（如 `zhihuishu.txt`）。

## 8. 决策记录

> 关键决策（ADR 风格，一事一条）追加在此节。

- **D1（2026-09-07）**：调研采用双轨方法论（Track A 现有实现扫描 + Track B 实地勘察），原则为不重复造轮子：第三方实现解决过的问题不从头摸索，但其选择器与接口结论一律以本地实测为准。
- **D2（2026-09-12）**：技术路线取**浏览器自动化为主**（Autovisor 模式），接口知识（fuckZHS）作后备优化储备。
- **D3（2026-09-12）**：反自动化纪律为 P0 工程红线（详见分析报告 Q5）；易盾滑块自动求解列为独立专项（有头 Chrome 下开发，人工工单兜底先行）。
- **D4（2026-09-12）**：凭据分平台文件 `data/passwords/zhihuishu.txt`；智慧树配置复用 `chaoxing_config.json` 通用段。
- **D5（2026-09-12，M2 实测）**：智慧树登录 Cookie 为会话级不落盘——每任务现场建态；M3 评估 storageState 恢复。
