## 发现的异常（按严重度）

### P1-1 账号失败但任务显示「执行完成 100%」
- 现象：`run-code` 30 秒超时导致账号 0 登录阶段 FAILED，但顶部横幅为「✅ 执行完成 100%」，阶段只走到第一步，泳道 0% 异常。
- 证据：`grade-t60s.png`（vision 分析确认矛盾显示）；日志：`Command 'playwright-cli ... run-code ...' timed out after 30 seconds` → `PROGRESS:[0] FAILED` → `Multi-account run complete. 1 account(s) processed.`
- 根因：`run_multi_account` 在子线程捕获异常后正常返回，`api.py` 仍发 `completed + DONE`；此前只补了「无凭证」预检，未覆盖账号级运行失败。
- 影响：用户会误以为任务成功。

### P1-2 内存采样把“无 Chrome 进程”当成探测失败
- 现象：未开浏览器时日志反复出现 `Memory sampler degraded: PowerShell probe failed:`；仪表盘「项目 Chrome 占用」长期显示 `—`。
- 根因：`memory.py` 的 PowerShell 脚本在 `Get-CimInstance` 无匹配进程时输出为空，`_run_ps` 把空输出判为失败；应输出 `0`。

### P1-3 账号增删改后 UI 列表不刷新
- 现象：添加账号后日志显示「账号已添加。」，但列表仍显示旧数据；刷新页面后才出现；删除同理。
- 根因：`account.store.fetchAccounts()` 有 `loaded` 缓存，`addAccount/editAccount/removeAccount` 后调用它直接短路。

### P2-4 设置页“当前账号文件”标签与实际生效文件不一致
- 现象：通过设置接口切换到临时账号文件后，账号列表已用临时文件，但标签仍显示 `data\passwords\chaoxing.txt` + 「默认」徽标。

### P2-5 停止任务后立即重启可能复用到卡死的 playwright 会话
- 现象：上一任务在 AI 调用中停止后，紧接着的新任务登录阶段 `pw_goto` 超时（run-code 30s）。
- 建议：新任务发现会话存在但页面异常时应关闭并重建会话。

### P2-6 进度显示失真
- 现象：任务仍在处理章节时整体进度已显示 100%；停止后的统计显示「10 章节 / 100% 完成率」（实际只处理到 1.1 节）。

### P2-7 其他
- 执行泳道计时器在无进度事件时冻结（两次采样均显示 ⏱ 38s）。
- 仪表盘「今日活动」在清空日志后归零（活动时间线依赖日志缓冲）。
- 设置页「任务运行中不可修改账号」提示在空闲时也常驻显示。
