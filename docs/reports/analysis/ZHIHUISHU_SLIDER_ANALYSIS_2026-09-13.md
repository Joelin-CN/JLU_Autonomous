# ZHIHUISHU_SLIDER_ANALYSIS_2026-09-13 — 易盾滑块自动求解可行性专项（P2-6）

- **类型**: 可行性专项（roadmap D3 立项，本次收尾出结论）
- **输入**: `ZHIHUISHU_ANALYSIS_2026-09-12.md`（M0 实测 Q1/Q5）、`ZHIHUISHU_REFS_2026-09-12.md`（Track A 参考矩阵）
- **结论先行**: **维持现状——登录降级链（storageState → 扫码工单 → 密码+滑块人工工单）不变；滑块自动化降级为「QR 登录失效时的后备专项」，不在当前 M 阶段实施。**

---

## 1. 问题背景

智慧树密码登录 100% 触发网易易盾滑块（弹窗 `.yidun_modal`、拼图 `.yidun_jigsaw`、
拖钮 `.yidun_slider`、隐藏字段 `NECaptchaValidate`）。M0 阶段（2026-09-12）做过
一次实测性预研，本轮专项对其结论做交叉复核并给出工程决策。

## 2. M0 实测事实复盘（ZHIHUISHU_ANALYSIS §Q1/§Q5）

在内嵌自动化浏览器（Playwright 默认环境，无 stealth）下 **4 次尝试全部被拒**：

| 维度 | 结果 | 说明 |
|------|------|------|
| 缺口定位 | ✅ 正确 | 截图像素边缘检测 + 拼图 PNG alpha 内偏移，误差 < 2px |
| 轨迹风格 1（缓动拟人） | ❌ 被拒 | 缺口处停止、缓动曲线 |
| 轨迹风格 2（Autovisor 随机分段） | ❌ 被拒 | 复刻参考项目轨迹生成 |
| 轨迹风格 3（过冲回正） | ❌ 被拒 | 人类常见过冲+回拉 |

**判定：拒绝发生在提交校验环节且与位置/轨迹无关 → 易盾做的是环境指纹检测**
（CDP 自动化特征、navigator/webgl/canvas 指纹等），不是行为分析。这意味着
在我们当前基础设施（playwright-cli 持久会话 + 默认 Chromium）上**无论把轨迹
调得多像人都会被拒**——优化方向错了。

## 3. 参考项目方案复核（ZHIHUISHU_REFS §2/§5）

- **Autovisor（浏览器路线标杆，MIT，2026-09 活跃）**：滑块可过的前提是
  **真实 Edge/Chrome + `stealth.min.js` 经 `add_init_script` 注入**——先消掉
  自动化指纹，再用 OpenCV 模板匹配定位缺口 + 随机分段轨迹。即：**指纹环境
  是过滑块的先决条件**，轨迹算法只是第二步。注意其弹题直接跳过不答题，
  与我们 M4 路线无关。
- **fuckZHS（纯 API 路线，MIT，2025-10 停更）**：完全绕开滑块 UI——服务端
  登录接口层面就不经过易盾（hike MD5 salt `o6xpt3b#Qy$Z` 等签名知识在案）。
  但 D2 ADR 已把 API 路线定位为备胎（无浏览器环境指纹收益的同时也失去
  D6「真实学习行为」的可辩护性，且接口签名随版本漂移风险高）。
- **Cooanyh（CC BY-NC-SA，仅思路）**：不碰滑块——掌握度页走已登录会话。

**本地 `references/` 未克隆 Autovisor 源码**（仅超星油猴脚本参考），本报告对
其滑块方案的复核基于 M0 Track A 调研记录（矩阵 §2 对 `modules/slider.py`
的拆解）。

## 4. 可行路径与成本评估

| 路径 | 做法 | 成本/风险 | 判定 |
|------|------|-----------|------|
| A. stealth 注入 | 在 playwright-cli 会话上注入 stealth 类脚本（等价 `add_init_script`）+ 复用 M0 已验证的缺口定位 | ①playwright-cli 对 init-script 的支持面需验证；②stealth 与易盾是持续军备竞赛，脚本时效无保证；③真实 Chrome 伪装仍需有头模式配合 D6 纪律 | **可行但投入产出差**：收益仅「密码登录免扫码」，而扫码工单路径 M0–M3 已被证明稳定可用 |
| B. 附加用户日常 Chrome | CDP attach 真实浏览器 | 与账号隔离（每账号独立 profile）冲突；引入用户日常浏览环境污染 | 否决 |
| C. 纯 API 登录 | fuckZHS 签名知识 | D2 已定位备胎；签名漂移 + 失去 D6 可辩护性 | 维持备胎定位 |

## 5. 决策

1. **维持现状**：登录降级链 = 持久 storageState 直进 → 扫码（QR 截图工单，
   M2 起生产验证）→ 密码+滑块（hint 工单指引人工去浏览器窗口拖拽）。
   现有 hint 工单流程不改动。
2. **滑块自动化降级为后备专项**，重评触发条件（满足其一）：
   - 智慧树 QR 扫码登录通道失效或风控收紧（扫码也要求滑块）；
   - 多账号高频登录场景使扫码人工成本不可接受；
   - stealth 方案在同类项目（Autovisor 系）出现持续 >1 个季度的稳定战报。
3. 届时优先路径 A，且必须在**有头真实 Chrome + 独立 profile** 下开发验证
   （D3 原始约束不变），实现形态优先「复用 M0 缺口定位代码 + 引入 stealth
   注入」，预计 2–4 天专项投入。
