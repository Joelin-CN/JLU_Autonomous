# PATH Fix Report - 2026-08-07

## Problem Description

项目从旧磁盘 `E:\B306\web\chaoxing.(xuexitong` 迁移到 `F:\Web\Chaoxing_auto` 后，存在以下问题：

1. `backend/chaoxing_config.json` 残留失效的旧盘绝对路径 `workspace_root: "E:/B306/web/chaoxing.(xuexitong"`（该路径已不存在）。
2. 多处硬编码机器相关 Python 解释器路径 `E:/Softwares/Anaconda/python.exe`（换机器 / 换解释器即断）。
3. `electron-builder.yml` 的 `extraResources` 采用「全量 + 排除」策略，未排除 `chrome-profiles/`（含登录态 cookie，约 432MB）、`screenshots/`、`documents/`、`etc/`、`tests/`，存在敏感数据被打进安装包的隐患。
4. `solver.py` 把临时 JS / 截图写入源码包目录 `chaoxing/solvers/quiz/`，导致临时垃圾文件（如 `tmp90t7oahm.js`）被误提交。
5. 目录结构与 monorepo 规范不一致：缺少根级 `data/`、`references/`、`AGENTS.md`、规范化的 `docs/` 布局；内部笔记 / 第三方脚本 / 真实配置被跟踪进公开仓库。

## Root Cause

- 磁盘迁移只搬运了文件，代码与配置中的绝对盘符路径未同步清理（`workspace_root` 为死配置，但示例被 README / 文档持续抄写）。
- 运行时产物目录与源码目录混放，且部分代码直接以 `os.path.dirname(__file__)` 作为临时文件目录，污染包目录。
- 打包配置使用黑名单式排除，遗漏了敏感 / 运行时目录。
- 项目缺少统一的「代码根 / 配置根 / 产物根」分层约定，环境变量只有 `CHAOXING_WORKSPACE` 单一路径。

## Fix Solution

### 1. 路径分层：新增 `CHAOXING_DATA_DIR` / `DATA_ROOT`

- `backend/chaoxing/constants.py` 新增 `DATA_ROOT`（默认 `WORKSPACE.parent / "data"`，可用 `CHAOXING_DATA_DIR` 覆盖），派生 `OUTPUT_DIR` / `TMP_DIR` / `LOG_DIR` / `SCREENSHOTS_DIR` / `CHROME_PROFILES_DIR` / `CREDS_DIR` / `DOCUMENTS_DIR`。
- 全部路径消费方（`logging_setup.py`、`platform/auth.py`、`platform/captcha.py`、`ai/billing.py`、`ai/doubao.py`、`orchestrator.py` 等）改为使用新常量。
- 前端 `backendPath.ts` 导出 `DATA_DIR`，`pythonBridge` 与三个 IPC handler（accounts / course / balance）透传 `CHAOXING_DATA_DIR`；`chaoxing_cli.ps1` 启动时设置该变量。
- `CHAOXING_WORKSPACE` 负责代码 / 配置根（dev：`backend/`，打包：`userData/workspace`）；`CHAOXING_DATA_DIR` 负责产物根（dev：仓库根 `data/`，打包：`userData/data`）。

### 2. 运行时目录迁至仓库根 `data/`

`backend/` 下 7 个目录整体迁移（数据保留，登录态不受影响）：

| 原路径 | 新路径 |
| --- | --- |
| `backend/passwords/` | `data/passwords/` |
| `backend/chrome-profiles/` | `data/chrome-profiles/` |
| `backend/screenshots/` | `data/screenshots/` |
| `backend/output/` | `data/output/` |
| `backend/temp/` | `data/temp/` |
| `backend/logs/` | `data/logs/` |
| `backend/documents/` | `data/documents/` |

### 3. 清理旧路径与硬编码

- 删除 `chaoxing_config.json` 的 `workspace_root` 字段，`config.py` 同步移除该属性（死配置）。
- `balance.py` / `ai/billing.py` / 各文档中的 `E:/Softwares/Anaconda/python.exe` 全部改为便携写法：专用 conda 环境 `chaoxing-backend` + `CHAOXING_BALANCE_PYTHON` 覆盖。
- `backend/README.md`、`docs/design/reference/API_REFERENCE.md` 中的旧配置示例同步更新。

### 4. 修复源码包污染

- `solver.py` 中 4 处 `os.path.dirname(os.path.abspath(__file__))` 临时文件目录改为 `TMP_DIR`。
- 删除被误提交的 `backend/chaoxing/solvers/quiz/tmp90t7oahm.js`。

### 5. 打包白名单

`electron-builder.yml` 的 `extraResources` 改为显式白名单：`chaoxing/**/*.py|js|json`、`scripts/` 三个只读资产、`chaoxing_config.json`、`requirements.txt`；敏感 / 运行时目录（passwords、chrome-profiles 等）绝不入包。

### 6. 仓库卫生与目录规范化

- 新增根级 `data/`、`references/`、`AGENTS.md`、`.gitattributes`、`docs/README.md` 索引。
- `docs/` 重构为 `design/`（api / integration / architecture / reference）、`changelog/`（CHANGELOG.md + archive/）、`reports/analysis/`、`sessions/`、`validation/`、`logs/`。
- `backend/etc/`（第三方脚本）迁至 `references/chaoxing-reference/`。
- `git rm --cached` 移除真实配置、`backend/etc/`、`backend/documents/`、`backend/.claude/plans/` 的跟踪；新增 `backend/chaoxing_config.example.json`。
- `.gitignore` 增加 `data/*`（保留 README）、`references/*`（保留 README）、`documents/`、`backend/chaoxing_config.json` 等规则。
- 创建专用 conda 环境 **`chaoxing-backend`**（Python 3.13 + `openai` + `volcengine-python-sdk` + pytest），前端默认 `pythonPath` 指向该环境。

## Impact Analysis

- **行为变更**：运行时产物根由 `backend/` 迁至仓库根 `data/`（打包后为 `userData/data`）；依赖旧路径的外部脚本 / 计划任务需同步更新。
- **兼容性**：登录态（`data/chrome-profiles/`）、凭证（`data/passwords/`）随目录整体迁移，不丢失；`CHAOXING_WORKSPACE` 语义不变。
- **安全提升**：安装包不再携带浏览器登录态；真实配置、第三方脚本、内部笔记不再进版本库。
- **注意事项**：
  - 已保存过前端设置的机器，`%APPDATA%\超星助手\settings.json` 中的 `pythonPath` 若为旧值，需在「系统设置」改一次或删除该文件。
  - 旧空目录（`docs/api`、`docs/reference` 等）与 `data/temp/_residue-*` 测试残留可手动清理（git 不跟踪）。
  - 本次仅执行了 `git rm --cached`（用户已授权），提交 / 推送由用户确认后自行执行。
