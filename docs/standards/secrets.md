# 凭据与敏感信息规范

> 本仓库为**公开仓库**，所有入库内容与 Issue / PR 讨论对全网可见。本文是红线，违反即事故。
>
> 版本 1.0 · 2026-09-07（随仓库打底建立）

---

## 1. 绝对不入库清单

以下内容**永远不得**出现在 git 跟踪文件、Issue、PR、评论、截图、日志粘贴中：

| 类别 | 具体形态 | 正确去处 |
| --- | --- | --- |
| 平台账号 | 手机号、密码、验证码、登录二维码截图 | `data/passwords/`（线下传递） |
| 浏览器登录态 | Chrome profile、session cookie | `data/chrome-profiles/`（自动生成） |
| API 密钥 | `ARK_API_KEY`、`DEEPSEEK_API_KEY`、火山 AK/SK、任何 `sk-` / `ark-` 串 | `data/passwords/*.txt` |
| 个人信息 | 真实姓名、学号、同学的手机号 / 姓名 | 不落任何仓库文件 |
| 真实配置 | `chaoxing_config.json`（含课程 ID / 学习进度） | 本地；入库只提交 `.example.json` |
| 环境文件 | `.env` 及任何变体 | 本地；提交 `.example` 模板 |
| 运行日志 / 截图 | 可能包含账号与课程细节的运行产物 | `data/logs/`、`data/screenshots/` |

`.gitignore` 已覆盖上述路径（`passwords/`、`chrome-profiles/`、`.env*`、`data/*` 等）；**新建目录若会产生敏感产物，必须同步补 `.gitignore` 规则**。

## 2. 示例与脱敏的写法

- 文档 / 测试代码中的账号示例统一用占位号段：`13200003918`、`13800000000`。
- 掩码展示格式：`132****3918`（前 3 + 后 4，与前端 `maskPhone` 一致）。
- 密钥示例：`ARK_API_KEY="ark-example-xxxx"`，禁止「拿真值改两位」式的伪脱敏。

## 3. 运行时凭据的传递

- 刷课需求的账号凭据由需求方**线下**交给接单管理者，写入本地 `data/passwords/` 对应文件，Issue 内只出现课程名与进度。
- 凭据文件格式见 `backend/README.md` 与 `data/README.md`；多人使用时靠 `account[N]` 索引区分，不靠真名。

## 4. 泄露应急流程

发现敏感信息已提交（无论哪个仓库）：

1. **立即作废**该凭据（改密码 / 吊销 Key）——这是一切后续操作的前提，git 删除不能替代作废；
2. 从当前分支删除并提交修复；若已进入 git 历史，用 `git filter-repo` 重写后强推，并通知所有本地克隆重建；
3. 在 `docs/reports/fixes/` 记录泄露与处置报告（不含泄露内容本身）；
4. 通知另一位管理者。

> 历史教训：原 Chaoxing_auto 仓库曾有一份验证文档引用了未打码的真实手机号（已在本仓库迁移时打码）。引以为戒：**复制粘贴真实日志进文档前，先扫一遍手机号与 Key 模式**。
